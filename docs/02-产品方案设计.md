# HS Copilot · 产品方案设计文档

> 版本 v0.3（随 AI-native 简化链路同步更新）｜ 2026-09-03

## 1. 产品定位

**一句话：描述商品，就能开始归类。**

HS Copilot 是面向外贸/报关从业者的智能归类助手。用户用大白话描述商品（或粘贴 HS 编码），产品通过"数据库 + 大模型"协同，给出可归因、可核验、可继续申报的 HS 编码建议。

**与纯大模型方案的本质区别**：所有编码、税率、申报要素等数字**只来自海关税则数据库**，大模型只负责理解、提问和判断，且最终输出必须命中数据库候选——从机制上杜绝"一本正经编编码"。

## 2. 目标用户与场景

- 报关行/货代操作员：拿到新商品，需要快速找到候选编码并确认关键属性；
- 外贸企业关务：核验供应商给的编码是否有效、税率和监管条件是什么；
- 跨境商家：不知道 HS 编码概念，只会描述商品。

## 3. 核心流程

### 流程 A · 商品归类（主流程，AI-native 链路）

```
首页输入商品描述
  → LLM 商品理解 + 查询计划（核心商品/功能/材质/结构/用途/规格 + 税则同义词 + 可能品目）
  → SQLite 宽松召回（同义词/关键词/CIQ俗名/品目展开三路合并，约 30~40 条真实候选，目标是不漏）
  → LLM 候选比较：找出最可能的候选与关键分歧，最多生成 1 个"最能改变判断"的问题
  → 确认页：左侧商品信息卡（已知属性实时回填），右侧关键问题确认
  → LLM 在原候选池上终选（不重新检索；仅商品本质改变才重召回）
  → SQLite 最终核验：编码名称/税率/监管条件/申报要素全部重新从数据库取
  → 结论页 → 继续完善申报信息（申报要素清单来自数据库，已知信息预填）
```

### 流程 B · 编码核验

输入含 10 位数字 → 直接查库 → 核验结果页（有效性、章节、税率、监管条件、申报要素数）。纯数据库查询，不消耗大模型，即时返回。

### 拒答策略

检索不到候选、或大模型判断候选均不匹配时，明确告知用户并建议补充描述/人工归类，**不给硬编造的答案**。

## 4. 页面设计

| 页面 | 职责 | 关键设计 |
|---|---|---|
| 首页 | 对话式输入入口 + 最近查询 | 大白话输入框、示例 chips、历史记录表格（可点击重放） |
| 关键确认页 | 确认影响归类的属性 | 左：商品信息卡（骨架屏→属性回填）；右：逐题问答 + "为什么要问"折叠解释 |
| 归类建议页 | 呈现结论与依据 | 大编码 + 置信度徽章 + 理由（打字机输出）+ 反事实（什么情况下结果会改变）+ 备选 + 右侧官方依据栏 + 海关官网核验跳转 |
| 申报信息页 | 申报要素完善 | 要素清单来自数据库，已确认的自动预填，行内点击编辑，一键复制（文本/表格） |

## 5. 交互细节（对标主流 AI 产品）

- **AI 思考进度**：等待大模型时显示分步进度（检索税则库 → 分析属性 → 生成问题），当前步骤转圈+流光文字，完成的打绿勾；
- **打字机结论**：归类理由逐条逐字打出（带光标），后续板块依次浮现；切到后台标签页时静默完成，不卡半截；
- **逐题确认**：选完一题自动进入下一题，左侧属性卡同步回填；
- **置信度透明**：高=关键属性已确认 / 中=建议人工复核 / 低=低置信度请人工复核；
- **官网核验**：结论页"在海关官网核验"一键跳转海关总署税率查询官网（新标签），并自动复制 10 位编码供粘贴查询。

## 6. 设计原则

1. **数字只信数据库**：编码、名称、税率、监管条件、申报要素全部出自 2026 版税则结构化数据；
2. **每条结论可核验**：依据栏展示税则品目、章节、排除候选的理由，海关官网核验入口已落实；
3. **诚实优于自信**：不确定就标低置信度或拒答，绝不硬答；
4. **少即是多**：大模型最多问 1 个问题，只问最能改变结论的属性；
5. **规格不污染召回**：ml/kg/cm/V/W/% 等单位参数只进入商品画像用于候选间判断，不参与关键词匹配。

## 7. 后续规划

终选裁定口径知识注入 → 大品目二次召回与延迟优化 → 图片/链接识别 → 云端部署多人使用 → 归类决定/案例库接入。
