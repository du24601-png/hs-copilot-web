# HS Copilot · 技术方案（简版）

> 2026-09-03 ｜ 对应代码：`hs-copilot-web/`（AI-native 简化链路 + 2026 税则规则知识层 + 独立判例层）

## 1. 总体架构

零构建、零框架依赖的轻量全栈：

```
浏览器（原生 HTML/CSS/JS 单页，4 个视图）
   │  fetch /api/*
   ▼
Node.js 原生 http 服务（server.js，无 Express）
   ├── SQLite（node:sqlite 内置驱动，只读）── hs_copilot.db（事实层 + 规则层 + 独立判例层）
   └── LLM API（OpenAI 兼容 chat/completions，多通道降级）
```

- **无 npm 依赖**：Node ≥ 22（用内置 `node:sqlite`；跑单测需 Node 24 的 `--test-isolation=none`），`node server.js` 即启动；
- 数据库文件随项目自包含，整个目录拷走即可运行。
- 日常服务不依赖 Python；仅离线重导规则或判例 Excel 时需要 Python 与 `tools/requirements.txt` 中的 `openpyxl`。

## 3. 数据层

- `hs_code`（12,032 行）：10 位编码、名称、税则"备注"栏（10 位级商品描述限定，**不是品目注释**）、最惠国/增值税/出口/消费税率、监管条件字母；
- `declare_element`（114,284 行）：编码 → 申报要素（按 seq 排序）；
- `ciq_code`（24,074 行）：CIQ 俗名对照，用于口语化商品名命中；
- `hs_fts`：FTS5 全文索引；`hs_chapter` 及若干参考表（监管证件、国别、口岸等）。
- `legal_source`：规则版本、源文件名、SHA-256、导入时间和统计；
- `tariff_scope`：21 类、97 章及类章父子关系；
- `legal_rule` / `legal_rule_scope`：304 条权威原文及其 global、类、章、8 位本国子目适用范围，其中 303 条可参与归类，1 条为独立合规提示；
- `legal_clause` / `legal_relation` / `legal_clause_fts`：643 个可检索条款、1,438 条机器提取的交叉引用及 FTS5 trigram 索引。
- 事实数据来源为 2026 年版进出口税则对照表；规则数据来自用户确认摘录自《中华人民共和国进出口税则（2026）》的 Excel。导入器保存原文、来源行、页码和源文件 SHA-256，机器只派生检索标签，不重写规则。
- `ruling_source` / `ruling_case` / `ruling_code_map` / `ruling_case_fts`：1个来源、104条历史判例、452条2026现行候选映射、trigram全文索引；保存27个原始字段、行号、内容哈希。27条唯一候选和77条多候选均是前缀匹配，全部pending，不代表人工确认归类。导入与备份详见 `12-独立判例层与对照验收.md`。

## 4. SQLite 宽召回（broadRecall）

设计目标是**不漏正确编码**（候选池约 30~40 条），排序精度交给后续 LLM。三路合并召回：

1. **LLM 规划词**：LLM① 给出的 `search_terms` / `hs_synonyms` 做品名匹配；
2. **原文基础关键词**：描述剥离规格单位后做中文 n-gram（4→2）匹配，所有长度命中都保留，无"命中即停"；
3. **CIQ 俗名表**：口语名 → 编码直接加分。

计分仅保留极简 IDF 档（+2 / +1 / +0.3），**没有任何位置/后缀/码序特殊加权**。规格与单位（ml、kg、cm、V、W、%、数字）只进商品画像，一律不参与召回匹配。

`possible_headings` 是信号不是门槛：建议品目整品目展开（≤12 条/品目，命中行优先、"其他"兜底码保护），同时关键词可从任意其他品目找回候选；裁池按分取前 30 + 每建议品目软保底 3 席。

### 4.1 规则知识查询

判例开启时，先在宽召回之后补充判例候选，再查询本节规则，确保新增候选也获得规则上下文。

宽召回完成后，服务端只做一次本地规则查询：候选 10 位码前 8 位命中本国子目注释，前 2 位命中章注并沿 `tariff_scope` 找到类注，同时读取六条 GRI。直接子目注释优先，其次是指向竞争税目的交叉引用、章注和类注；商品词仅用于同层条款排序。

规则上下文设固定字符预算并随会话缓存，普通追问不重复查询，也不增加 LLM 调用。若用户补充使商品本质改变并触发重新召回，候选和规则上下文同步刷新。“禁止进口”等合规信息走独立 `complianceNotices` 字段，不参与选码。

### 4.2 归类依据回溯（queryCodeBasis）

终选定码后，服务端按**选中编码**主动检索“针对性归类依据”供结果页展示，不依赖 LLM 引用的 `applied_rule_ids`：① 该 8 位子目的本国子目注释；② 本品目所属章的章注中**点名该品目号**（如“85.39”）的条款。前端依据区优先级为 `codeBasis`（具体条款）→ LLM 引用的非 GRI 规则 → GRI（通用方法，兜底）→ 诚实提示，避免结果页只显示泛泛的 GRI 总规则。此检索纯用现有数据库，不增加 LLM 调用。

## 5. LLM 三阶段链路（全部 temperature = 0）

判例开启后的普通流程仍是三次调用：商品理解 → 原宽召回＋文本/编码双路判例检索 → 补充最多20个真实现行候选（保留原候选）→ 规则查询 → 候选与判例事实比较 → 用户确认 → 终选并核验。最多6条判例、6000字符；两字中文LIKE补查，英文按整词检索，编码范围不能阻断跨税目文本召回。无商品文本匹配的判例不得补充编码。

比较/终选均可输出 `case_assessments`（`case_id`、`supports|distinguishes|uncertain`、相同事实、差异、解释）。服务端只接受该次提示词实际包含的ID，返回 `caseReferences` 与 `caseKnowledgeStatus`；公告、原文、历史税号、来源由库回填。历史判例不能覆盖现行规则，正文及用户描述仅是待分析数据。

会话缓存键包含查询串、判例开关和来源版本。重召回同步更新候选、规则和判例，空召回明确拒答并清空旧证据。缺表或查询失败返回明确降级状态；`HS_RULINGS=0` 保持原归类链路。`HS_DB_PATH` 可指定隔离测试库；显式指定不存在时不偷偷回退主库。`/api/hs/:code` 与搜索联想不调用模型。

| 阶段 | 接口 | 输入 | 输出（固定 JSON） |
|---|---|---|---|
| LLM① 理解+规划 | `POST /api/classify` | 商品描述 | core_product / function / materials / structure / usage / specifications / search_terms / hs_synonyms / possible_headings |
| LLM② 候选比较 | `POST /api/classify` | 商品画像 + 30~40 条真实候选 + 候选适用规则 | plausible_candidates / 关键差异 / 至多 1 个问题 / relevant_rule_ids |
| LLM③ 终选 | `POST /api/decide` | 画像 + 用户答案 + **原候选池和规则上下文** | 最终编码、理由、反事实、备选、applied_rule_ids、拒答 |

- **会话复用**：classify 缓存画像 + 候选池 + 规则/判例上下文 + 比较结论（24h）；decide 不重新检索，仅当 LLM③ 判定商品本质改变且答案确有新信息时才同步重召回（每轮 ≤1 次）；
- **安全钳制**：模型输出的编码必须命中候选池、规则 ID 必须命中本轮数据库上下文，否则剔除；自由文本先剥离用户声称的 HS 编码；名称、规则原文、税率、监管条件、申报要素等权威字段一律从数据库返回，**不使用模型返回的任何数值或自造规则**；
- **降级**：LLM① 失败时 fallbackProfile 仅用原文关键词召回，并向前端透传 degraded 提示。

**模型通道（llm.config.json，按序降级）**：
1. DeepSeek `deepseek-v4-flash`（主通道，支持 `response_format: json_object`）；经 `extraBody` 传 `thinking:{type:"disabled"}` 关闭深度思考——V4 系列默认开 thinking，单例耗时可飙到分钟级，关闭后单例约 15s；
2. DeepSeek `deepseek-chat`（兜底）；
3. OpenCode 免费模型（最后兜底，有按分钟限流，429 时等 12s 重试）。

每通道按 通道×模型 依次尝试；provider 可选 `extraBody` 会合并进请求体（用于关闭 thinking 等厂商特定参数，默认无则行为不变）；JSON 解析失败（含 think 标签、非 JSON 输出）自动切换下一个。

## 6. 前端要点

- 视图路由：`go(name)` 切换 4 个 section；
- 历史记录：localStorage（最近 50 条），classify 记录存完整 result 供重放；
- 确认页动态渲染：左卡属性（骨架屏→已知属性→待确认回填），右侧逐题 radio + 事件委托；
- 进度组件：分步定时推进，最后一步保持转圈直到接口返回；切后台时定时器被节流也不影响完成；
- 打字机：按墙上时钟计算应显字数（抗后台节流），`document.hidden` 时直接打满；用递增 token 作废切页前的旧任务；`renderReasons`/`doReveal`/`showDecisionLLM` 带 instant 开关，历史记录回放走 instant 分支直接铺满理由并即时浮现后续板块，不启动打字机；
- 结论页“在海关官网核验”：跳转海关总署税率查询官网（新标签）并自动复制 10 位编码；
- 结论页背景信息（P0+B）：系统识别的商品属性回溯、完整 5 种税率、监管证件名称、合规提示，以及“归类依据·税则原文”——优先展示本国子目注释与章注点名该品目的条款（附来源页码、可核验），GRI 降为兜底；
- 独立“参考判例”区：支持/区别/不确定三类，AI分析与原文分开；缺日期或裁定叙述不补写，缺失/截断网址不生成链接，不展示本机路径。旧记录显示“未保存判例信息”，切到纯编码核验隐藏旧归类证据。
- 常见问题弹窗：顶栏“帮助”打开 `#faqModal`，FAQ 数据内置于 `app.js`（`FAQ_ITEMS`，7 条），首次打开渲染并缓存；标题点击用事件委托切换 `.open`，答案区以 CSS `grid-template-rows: 0fr→1fr` 平滑展开；支持关闭按钮 / 遮罩点击 / Esc 关闭。
- 申报页：要素清单来自当前编码的数据库记录，已知信息按规则预填（精确匹配→包含匹配，跳过“不确定”），行内编辑，一键复制。

## 7. 部署与运行

```bash
cd hs-copilot-web
node server.js        # 默认 http://127.0.0.1:7100/
```

目前为本地运行。上云时：整目录上传 + 进程守护（pm2/systemd）+ 反向代理即可；数据库只读，无需额外服务。

## 8. 已知限制与迭代方向

- **判例适用性仍待业务确认**：104条已接入独立证据层，不代表已确认当前有效；前缀映射不是确定映射，模型仍需比较实际事实。默认开关以本轮对照验收结果为准；
- **大品目展开受限**：8703/8481/9018/3824 等品目超 12 行展开上限，计划支持 LLM 请求"展开某品目更多行"的二次召回；
- **延迟约 15s**（3 次串行 LLM + 大候选 prompt）：计划裁剪候选 prompt、理解+召回管线化；
- 明确**不引入**向量数据库 / Agent / 多智能体框架（本轮验证结论：简化架构已优于旧检索，不再堆机制）；
- API Key 明文存于 `llm.config.json`，生产环境应改为环境变量/密钥管理；
- 单一窗口格式导出、图片/链接识别为预留未实现功能。
