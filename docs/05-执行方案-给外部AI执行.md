## 0. 给执行者（AI）的三条工作方式

1. **一次只做一个批次。** 完成一个批次 → 跑完该批次的验收 → 把验收输出贴给用户 → **等用户说"继续"再进入下一批次**。不要一口气做完四个批次。

## 2. 为什么改（背景，务必先理解）

MVP 工程已完成，但**归类准确性从未被验证**。实测三个案例全部失败：

| 输入 | 正确编码 | 当前结果 |
|---|---|---|
| 不锈钢真空保温杯 500ml | 9617.00.90 | **完全没进候选池** |
| 实木蓝牙音箱 | 8518.22 | 排第 13，被 8418 冷藏箱淹没 |
| 电动牙刷 | 8509803000 | 排第 13，被 8443 印刷机淹没 |

**根因不是 AI 笨，是检索把正确答案挡在门外了**——AI 只能在检索给的 16 条候选里挑，正确答案不在里面，AI 再聪明也没用，只能硬编一个（实测它编了 7323.93.00）。

四个致命缺陷（行号为当前 HEAD）：

| # | 缺陷 | 位置 | 说明 |
|---|---|---|---|
| 1 | 切词命中即停止 | `server.js:141-151` | "不锈钢真空保温杯"里，`n=3` 时"不锈钢"先命中，`matched=true` 直接跳出所有长度层，"保温""杯"永远没被计分 |
| 2 | AI 查询扩展从未被调用 | `server.js:371` | 触发条件 `if (distinctHeadings < 3)` 用"结果数量"判断"结果质量"。保温杯案例检索出 4 个品目（全错），不满足 `<3`，**AI 扩展一次都没跑过** |
| 3 | 品目名额只取前 4 个家族 | `server.js:185` | 正确答案 9617 排在第 5 家族，直接出局 |
| 4 | 首页搜索整串精确匹配 | `server.js:84` | FTS 整串短语匹配，口语长句必返回空 |

**一句话改造方向：让 AI 从"检索完才参与"变成"先规划再检索"。**

## 3. 绝对不能改的底线（改了就是破坏产品）

1. **安全钳制**：模型输出的编码必须命中候选集（`sanitizePhase1` / `sanitizePhase2` 里的 `codes.has(...)` 校验，一个字都不能删）。
2. **权威数据只来自数据库**：编码名称、税率、申报要素一律用 `getHsRow()` 回查覆盖，不采用模型给的任何数值。
3. **编码核验路径不动**：`apiHsCode`（`server.js:60-67`）是纯数据库直查，不消耗 LLM，工作正常。
4. **禁止引入任何依赖**：不装 npm 包，不引入框架，不加向量库。
5. **不碰 `llm.config.json`**，不把它写进任何提交。

## 4. 验收工具：探针脚本

**`tools/probe-candidates.cjs` 已创建并验证可用，改前基线已采集到 `tools/baseline-before.txt`（见 §4.1）。** 不要重写它，直接用它验收。内容如下（供参考）：

```js
// tools/probe-candidates.cjs —— 候选集命中率探针
// 用法: node tools/probe-candidates.cjs "不锈钢真空保温杯 500ml" "实木蓝牙音箱" "电动牙刷"
const EXPECT = {
  '不锈钢真空保温杯 500ml': '9617',
  '实木蓝牙音箱': '8518',
  '电动牙刷': '8509',
  '铝合金 iPad 触控笔': '9608'
};
const QUERIES = process.argv.slice(2).length ? process.argv.slice(2) : Object.keys(EXPECT);

(async () => {
  let pass = 0;
  for (const q of QUERIES) {
    let d;
    try {
      const r = await fetch('http://127.0.0.1:7100/api/classify', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ query: q })
      });
      d = await r.json();
    } catch (e) {
      console.log('\n=== ' + q + ' ===\n请求失败: ' + e.message + '（服务起来了吗？）');
      continue;
    }
    const list = d.candidates || [];
    const want = EXPECT[q];
    const idx = want ? list.findIndex(c => c.code.startsWith(want)) : -1;
    const ok = want ? idx >= 0 && idx < 3 : null;
    if (ok) pass++;
    console.log('\n=== ' + q + ' ===');
    console.log(want
      ? (idx >= 0 ? `结果: 命中 #${idx + 1}（期望前缀 ${want}，需进前 3）${ok ? ' [PASS]' : ' [位置不达标]'}`
                  : `结果: 未命中（期望前缀 ${want}） [FAIL]`)
      : '结果: 无期望值，仅打印候选');
    console.log('productName: ' + (d.productName || '-') + ' | confidence: ' + (d.confidence || '-') + ' | converged: ' + (d.converged === undefined ? '-' : d.converged));
    list.forEach((c, i) => console.log(String(i + 1).padStart(2) + '. ' + c.code + '  ' + c.name));
  }
  console.log(`\n---- 汇总: ${pass}/${QUERIES.filter(q => EXPECT[q]).length} 个已知案例进前 3 ----`);
})();
```

**使用注意：**
- **服务必须保持运行**。启动命令不要加 `&` 后立刻关闭终端——进程会随终端退出被回收，探针会报 `fetch failed / ECONNREFUSED`。请单独开一个终端常驻运行 `node server.js`。
- 每次改完 `server.js` **必须重启服务**（`classifyCache` 是 24 小时内存缓存，不重启会一直拿到旧结果）。
- 用 `fetch` 而非 `curl`：本机环境设了 `HTTP_PROXY=http://127.0.0.1:65097`，`curl` 会走代理被拦截返回 502（除非加 `--noproxy '*'`）。已实测 Node 的 `fetch` **不受该代理影响**，可直连 127.0.0.1。
- 基线已采集，见下节。改动过程中随时重跑对比。

## 5. 批次 1：AI 前置查询规划（约 30 行，收益最大）

> **为什么排在修 bug 前面**：改成 AI 先规划后，AI 会生成"保温瓶"这类税则用语作为检索词，**直接绕开**缺陷 1（切词 break），而不是修补它。花 30 行先验证方向对不对，比先花 20 行修算法更划算。

### 1.1 用查询规划替换查询扩展

**位置**：`server.js:192-208`（`EXPAND_SYSTEM` 常量 + `expandCache` + `llmExpand` 函数）
**操作**：整段替换。

`llmExpand` 只在 `candidatesFor`（`server.js:372`）被调用一次，删除不影响其他逻辑。

替换成以下代码（含提示词，直接粘贴）：

```js
/* 查询规划：让 LLM 把口语描述拆成四层，指导税则库检索。
   与"字面检索"并行发起；失败返回 null，调用方回退到纯字面检索结果。 */
const PLAN_SYSTEM = `你是中国海关 HS 归类助手。用户给出一个商品描述（可能是口语化大白话）。
任务：把描述拆解成四层，用于指导税则数据库检索。

四层定义与判定规则：
1. core（核心商品）——这个东西"是什么"，回答"它属于哪一类物品"
   - 判据：去掉所有修饰词后剩下的那个名词
   - 正例：「不锈钢真空保温杯」→核心是「保温杯」，不是「不锈钢」
   - 反例：「铝合金 iPad 触控笔」→核心是「触控笔」，铝合金和 iPad 都不是
2. structure（关键结构）——影响归类的结构/功能特征，如「真空」「折叠」「带电加热」
3. material（材质）——制成材料，如「不锈钢」「实木」「铝合金」
4. params（规格参数）——容量/尺寸/功率/型号。逐项标注 affectsCode：
   - true  = 该参数会影响编码（如冷藏箱按容积分档、电机按功率分档）
   - false = 该参数只用于申报，不影响编码（如保温杯的 500ml）

还要输出：
- core.alt：税则品名中可能出现的同义说法。海关税则用语与口语差异很大，
  例如口语「保温杯」在税则里叫「保温瓶」。请给出 2-4 个税则里可能出现的说法。
- core.chapters：该商品可能所属的 HS 章节号（2 位数字字符串），最多 3 个，
  按可能性排序。税则共 96 章，你给的章节会用于库内兜底检索，宁可多给不要漏给。

只输出 JSON，不要任何解释文字、不要代码块标记：
{"core":{"word":"","alt":[],"chapters":[]},"structure":{"word":""},"material":{"word":""},"params":[{"key":"","value":"","affectsCode":false}],"confidence":"high|medium|low"}`;

const planCache = new Map();
async function llmPlan(query) {
  if (planCache.has(query)) return planCache.get(query);
  const messages = [
    { role: 'system', content: PLAN_SYSTEM },
    { role: 'user', content: '商品：' + query }
  ];
  const { data } = await llmChat(messages, { quick: true });
  const root = data && typeof data === 'object' ? data : {};   // 模型可能返回 null / 非对象
  const plan = {
    core: {
      word: String((root.core && root.core.word) || '').slice(0, 20),
      alt: (Array.isArray(root.core && root.core.alt) ? root.core.alt : []).map(String).slice(0, 6),
      chapters: (Array.isArray(root.core && root.core.chapters) ? root.core.chapters : [])
        .map(c => String(c).replace(/\D/g, '').slice(0, 2)).filter(c => c.length === 2).slice(0, 3)
    },
    structure: { word: String((root.structure && root.structure.word) || '').slice(0, 20) },
    material: { word: String((root.material && root.material.word) || '').slice(0, 20) },
    params: (Array.isArray(root.params) ? root.params : [])
      .filter(p => p && p.key).slice(0, 6)
      .map(p => ({ key: String(p.key).slice(0, 12), value: String(p.value || '').slice(0, 20), affectsCode: !!p.affectsCode })),
    confidence: ['high', 'medium', 'low'].includes(root.confidence) ? root.confidence : 'low'
  };
  planCache.set(query, plan);
  return plan;
}
```

> **注意**：`llmExpand` 原本内部 `catch` 了异常返回 `[]`。这里**故意不 catch**——由调用方统一 `.catch(() => null)`，让"规划失败"和"规划成功但结果差"是两条清晰路径。

### 1.2 重写 `candidatesFor`：并行 + 分层合并

**位置**：`server.js:367-376`
**操作**：整段替换。

```js
// 只取 code 数组，便于分层加权合并
function codesFor(text) {
  if (!text) return [];
  return retrieveCandidates(String(text)).map(c => c.code);
}

// 章节兜底：在指定章内按词检索；无词或无命中时取该章前若干条
function codesInChapter(chapter, word) {
  const ch = String(chapter).replace(/\D/g, '').slice(0, 2);
  if (ch.length !== 2) return [];
  if (word) {
    const rows = db.prepare('SELECT code FROM hs_code WHERE code LIKE ? AND name LIKE ? LIMIT 30')
      .all(ch + '%', '%' + word + '%');
    if (rows.length) return rows.map(r => r.code);
  }
  return db.prepare('SELECT code FROM hs_code WHERE code LIKE ? LIMIT 12').all(ch + '%').map(r => r.code);
}

const PLAN_WEIGHT = { base: 2, core: 3, alt: 2, chapter: 1.5, structure: 2, material: 0.5, param: 1 };

// 检索候选：AI 四层规划 与 原始字面检索 并行发起，分别检索后加权合并
async function candidatesFor(query) {
  const t0 = Date.now();
  const [plan, base] = await Promise.all([
    llmPlan(query).catch(e => { console.warn('[plan]', e.message); return null; }),
    Promise.resolve(retrieveCandidates(query))
  ]);
  if (!plan) return base;

  const score = new Map();
  // 排名靠前的多加一点分；同一批内第 n 名权重 (1 - n*0.02)
  const bump = (codes, w) => (codes || []).forEach((code, i) => {
    if (!code) return;
    score.set(code, (score.get(code) || 0) + w * (1 - Math.min(i, 20) * 0.02));
  });

  bump(base.map(c => c.code), PLAN_WEIGHT.base);                       // 原始词面结果保底入池
  bump(codesFor(plan.core.word), PLAN_WEIGHT.core);                    // 核心商品：最高权重
  plan.core.alt.forEach(w => bump(codesFor(w), PLAN_WEIGHT.alt));      // 税则同义说法
  plan.core.chapters.forEach(ch =>                                     // 章节兜底：猜章比猜品名容易
    bump(codesInChapter(ch, plan.core.word || plan.structure.word), PLAN_WEIGHT.chapter));
  bump(codesFor(plan.structure.word), PLAN_WEIGHT.structure);          // 关键结构
  bump(codesFor(plan.material.word), PLAN_WEIGHT.material);            // 材质：只加分，不主导
  plan.params.filter(p => p.affectsCode && p.value)                    // 仅影响编码的参数参与
    .forEach(p => bump(codesFor(p.value), PLAN_WEIGHT.param));

  const ranked = [...score.entries()].sort((a, b) => b[1] - a[1]);
  // 多样性保底：同一品目（前 4 位）最多 6 条，避免一个超大品目霸榜
  const perHeading = new Map();
  const picked = [];
  for (const [code] of ranked) {
    const h = code.slice(0, 4);
    const n = perHeading.get(h) || 0;
    if (n >= 6) continue;
    perHeading.set(h, n + 1);
    picked.push(code);
    if (picked.length >= 16) break;
  }
  console.log('[plan]', JSON.stringify(plan), (Date.now() - t0) + 'ms');
  const merged = picked.map(getHsRow).filter(Boolean);
  return merged.length ? merged : base;
}
```

**实现要点（不要图省事跳过）：**

- **必须并行**：`llmPlan` 是网络请求（约 2-5 秒），`retrieveCandidates` 是本地查询（几十毫秒）。串行会让每个请求凭空多等几秒。
- **必须分别检索再合并**：**不要**写成 `retrieveCandidates(query + ' ' + altWords)`。把扩展词混进原始 query 会被缺陷 1 的切词逻辑吞掉，等于白做。
- **原始结果要保底入池**（`PLAN_WEIGHT.base`）：万一 AI 规划跑偏，字面检索的结果还在，不会比改之前更差。

**性能注意事项（先看一眼，别等慢了再查）：**

分层合并会调用 `retrieveCandidates` 约 8-12 次（核心词 + 最多 6 个 alt + 3 个章节 + 结构 + 材质 + 参数），每次内部又有约 10 次 `LIKE '%x%'` 全表扫描（12,032 行）。粗估增加 1-2 秒。因为与 LLM 请求并行，实际体感增加有限，但**必须实测**。

如果验收时延迟超标（> 6s），按这个顺序优化，**不要一上来就砍功能**：

1. **把 `hitsCache` 从 `retrieveCandidates` 内部提到模块级**（跨调用复用同一关键词的查询结果）——最简单，通常能砍掉一半以上耗时。
2. 把 `plan.core.alt` 从 6 个降到 3 个。
3. 把 `plan.core.chapters` 从 3 个降到 2 个。

## 7. 批次 3：两轮降维循环（约 40 行）

### 7.1 思路

- **触发信号用"分数集中度"**（纯数值，不问 AI）：候选里 top1 品目占比高 = 方向明确；分散在 4 个品目各 25% = 瞎蒙。
- **第二轮策略是"降维"，不是"重复"**：具体品名搜不到，就退到上位词。实测"保温杯"全库 0 条 → "保温"有 6 条（含正确答案 9617）→ "容器"大量命中。**上位概念在库里必然存在，降维一定命中。**
- **防锚定**：第二轮必须显式指令"忽略第一轮结果"，否则 AI 会沿着错误方向（比如冷藏箱）越走越远。
- **最多 2 轮**。第三轮边际收益低于延迟代价。

### 7.2 实现

**（a）新增集中度函数**，放在 `candidatesFor` 之前：

```js
// 分数集中度：占比最高的品目（前4位）占候选总数的比例。高 = 方向明确，低 = 瞎蒙
function concentration(cands) {
  if (!cands.length) return 0;
  const byH = new Map();
  for (const c of cands) { const h = c.code.slice(0, 4); byH.set(h, (byH.get(h) || 0) + 1); }
  return Math.max(...byH.values()) / cands.length;
}

// 第二轮：降维重搜。显式要求忽略第一轮，退到上位概念重新规划
const PLAN_SYSTEM_R2 = `你是中国海关 HS 归类助手。上一轮按商品的具体名称检索税则库失败了——税则用语与口语差异很大（例如口语「保温杯」在税则里叫「保温瓶」，但也可能压根不使用这个词）。
现在请【完全忽略上一轮的结果】，从更上位的概念重新开始：
1. 把这个商品退到它的上位品类。例：保温杯 → 保温容器 / 家用器皿 / 真空容器。
2. 给出上位品类在税则里可能的品名说法（alt），以及可能所属的章节号（chapters，最多 3 个）。
3. 不要重复上一轮已经试过的具体词。

只输出 JSON，不要任何解释文字：
{"core":{"word":"","alt":[],"chapters":[]},"structure":{"word":""},"material":{"word":""},"params":[],"confidence":"high|medium|low"}`;

async function llmPlanRound2(query, firstPlan) {
  const messages = [
    { role: 'system', content: PLAN_SYSTEM_R2 },
    { role: 'user', content: '商品：' + query + '\n上一轮已尝试（请避开这些词）：' +
      JSON.stringify([firstPlan.core.word, ...firstPlan.core.alt, firstPlan.structure.word, firstPlan.material.word].filter(Boolean)) }
  ];
  const { data } = await llmChat(messages, { quick: true });
  const root = data && typeof data === 'object' ? data : {};   // 模型可能返回 null / 非对象
  return {
    core: {
      word: String((root.core && root.core.word) || '').slice(0, 20),
      alt: (Array.isArray(root.core && root.core.alt) ? root.core.alt : []).map(String).slice(0, 6),
      chapters: (Array.isArray(root.core && root.core.chapters) ? root.core.chapters : [])
        .map(c => String(c).replace(/\D/g, '').slice(0, 2)).filter(c => c.length === 2).slice(0, 3)
    },
    structure: { word: String((root.structure && root.structure.word) || '').slice(0, 20) },
    material: { word: String((root.material && root.material.word) || '').slice(0, 20) },
    params: [],
    confidence: 'low'
  };
}
```

```js
// 每个选项背后挂着候选编码子集，用户选中后前端当场筛一遍
function applyAnswer(cands, opt) {
  if (!opt.codes || !opt.codes.length) return cands;          // 「不确定」类选项：不过滤
  const keep = new Set(opt.codes);
  return cands.filter(c => keep.has(c.code));
}
// 收敛 = 剩余候选 ≤ 1，或剩余候选中 top1 品目占比 ≥ 0.6
```
