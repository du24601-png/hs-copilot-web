# 出海电商数据集（export-seller-noisy-20）

## 测试目标

模拟真实外贸 / 跨境电商卖家：用户只输入一段带营销噪声的商品描述，系统最终建议的 10 位编码是否正确。与 `docs/06` 的"真实商品 20 例"（海关疑难判例）互补——本集聚焦**跨境电商常见消费品**，反映系统在实际出海业务主力品类上的表现。

## 与"真实商品 20 例"的区别

| 维度 | 真实商品 20 例（docs/06） | 出海电商数据集（本文档） |
|---|---|---|
| 商品类型 | 海关归类决定疑难判例 | 跨境电商常见消费品 |
| 答案来源 | 海关总署归类决定 + DB 映射 | DB 核验编码存在且品名一致 + 联网核实 |
| 答案性质 | 海关个案裁定口径 | **规范归类判断**（非个案裁定），争议者在 `difficulty` 注明取舍 |
| 难度 | 高（个案口径缺失） | 中（常见品，细分/争议） |
| 用途 | 攻准确率天花板 | 反映主力业务表现 |

## 答案从哪里来

1. 每个商品先在 `hs_copilot.db`（2026 版）验证 10 位编码真实存在、库内品名与商品一致；
2. 再联网核实归类口径（税则条文 / 海关答复 / 实务），修正错误编码（如手提袋、非真空餐盒、水槽等曾据实修正）；
3. 描述用卖家口吻（营销话术 + 规格 + 材质 + 用途），并**显式排除易混归类**（如"不是有线耳机""不抽真空保温"）；
4. 对有归类争议的商品（蓝牙耳机 8517/8518、移动电源 8507/8504 等），在 `difficulty` 字段注明本集取舍口径。

## 数据结构和运行方法

- 数据集：`test/fixtures/export-seller-noisy-20.json`
- 跑分程序：`tools/test-export-seller-20.cjs`（含 `simulateAnswer` **模拟用户答题**：classify 追问时，选择命中 `expectedCode` 的选项；无命中则补充商品描述）
- 结果留档：`tools/export-seller-20-result.json`

```powershell
node server.js --port 7113          # 终端 A：启动服务（v4-flash 主通道）
node tools/test-export-seller-20.cjs --base-url http://127.0.0.1:7113   # 终端 B：跑分
```

## 最新结果（v4-flash 关 thinking + 模拟答题）

| 指标 | 成绩 |
|---|---:|
| Final Correct | **17/20（85%）** |
| Heading Recall / HS10 Recall | 20/20（100%） |
| 追问率 | 10/20 |
| Refusal / Error | 0 / 0 |
| 平均延迟 / P95 | ~10.8s / ~13.7s |

3 例未命中均为细分 / 争议，非硬错：
- **001 保温杯**：9617001900 → 9617009000（同品目 9617 内细分，唯一真错）；
- **002 蓝牙耳机**：8517629400 → 8518300000（8517/8518 归类争议，系统选 8518 也是主流口径）；
- **017 塑料水壶**：3924100000 → 3924900000（3924 内细分争议）。

## 解释结果时的边界

本集是跨境电商**常见消费品**，反映出海业务主力品类的表现（85%、召回 100%）；**不代表疑难判例准确率**（见 `docs/06` 真实集 7/20）。两集共同说明：系统召回强（正确编码几乎都进池），瓶颈在**终选细分**与**判例知识缺失**——这也是下一步判例层（第 7 步）要攻的方向。
