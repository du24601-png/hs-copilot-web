# HS Copilot 部署清单（阿里云 + Ubuntu）

> 当前采用 GitHub 拉取部署，请优先使用 [GITHUB-DEPLOY.md](GITHUB-DEPLOY.md)。下文保留早期压缩包部署流程。
> 当前 Nginx 方案让应用监听 `127.0.0.1:7100`，不需要将应用端口暴露到公网。

> 针对 `hs-copilot-web` 定制。结论先说：这个项目**零 npm 依赖、数据库只读**，
> 是部署友好度最高的一类——服务器上不用 `npm install`，更新数据库前仍需保留数据副本。
>
> 本清单是「腾讯云版」的阿里云改写版，并配套两个脚本，全程在 **Windows PowerShell** 里就能操作：
> - `deploy/pack.ps1`：本机一键打包（自动剔除 `.git`/旧库快照/大 PDF/密钥，产物约 7MB）
> - `deploy/setup-server.sh`：服务器一键装环境（Node 24 + pm2 + nginx）

## 你的项目部署画像（已实测确认）

| 项目 | 实况 | 对部署的影响 |
|---|---|---|
| 依赖 | 零 npm 包，纯 Node 内置模块 | 不用 `npm install`，部署快 |
| 数据库 | `hs_copilot.db` 23.4MB，**只读打开** | 运行期不修改数据库，更新前保留数据副本 |
| Node 版本 | 本地开发用 v24 | 服务器装 **Node 24**（最低 v22.5，否则 `node:sqlite` 不可用） |
| 监听地址 | 默认 `127.0.0.1:7100` | 使用 `HOST=127.0.0.1`，由 Nginx 对外转发 |
| 大模型 | DeepSeek 等，国内服务器直连 | 不需要代理 |
| 密钥 | `llm.config.json`（gitignore） | 打包时**单独排除**，需单独上传并 `chmod 600` |
| 静态资源 | 白名单已加固 | `/llm.config.json`、`/server.js`、`/hs_copilot.db` 均返回 403 |
| 判例层 | `HS_RULINGS=0` 默认关闭 | 需要时改 `deploy/ecosystem.config.cjs` 里的值为 `1` |

## 第一步：买阿里云服务器

### 推荐：轻量应用服务器（Simple Application Server）

对本项目最合适——操作最简单、自带公网 IP、控制台有独立「防火墙」、价格亲民，
和腾讯云轻量是同类产品。**不要一上来买 ECS**（要自己配实例规格/带宽/安全组，复杂且更贵）。

**购买路径**：阿里云官网 → 搜索「轻量应用服务器」→ 立即购买
（或产品页 `https://www.aliyun.com/product/swas`）

**选配建议**：

| 项 | 选择 | 说明 |
|---|---|---|
| 地域 | 华东1（杭州）/ 华北2（北京）/ 华南1（深圳） | 选离你近的；调用 DeepSeek 与地域无关 |
| 镜像 | **系统镜像 → Ubuntu 24.04 LTS（64位）** | 选「系统镜像」而非「应用镜像」，详见表下说明 |
| 套餐规格 | **2核2G** 起 | 本项目极轻，2核2G 跑几十并发没问题 |
| 带宽/流量 | 3~5 Mbps、月流量 300G+ 的活动套餐 | 文本应用，带宽要求很低 |
| 时长 | 先买 **1 个月或 1 年** | MVP 阶段别买 3 年 |
| root 密码 | 购买时设置，**记牢** | 轻量默认 root 登录；忘了可在控制台重置 |

> **镜像别选错**（购买页镜像分两类）：
> - **系统镜像**（纯净 OS）→ **选这个**：**Ubuntu 24.04 LTS**，架构 **64 位 / x86_64**。
>   环境由 `setup-server.sh` 自己装（Node 24 + pm2 + nginx），干净可控。
> - **应用镜像**（预装 WordPress / Node.js / 宝塔面板等）→ **不要选**：预装的 Node 常是旧版（16/18），
>   本项目需要 Node 24 的 `node:sqlite`，旧版跑不起来；宝塔等面板也徒增开销。
>
> 万一列表里没有 24.04，退选 **Ubuntu 22.04 LTS** 也行；**别选** CentOS（已停维护）、
> 非 LTS 版（如 25.04）、Windows Server（本清单全是 Linux 命令）。

**价格**：阿里云轻量常年有新用户/活动价，2核2G 常见 ¥几十~一百多/年区间，
**以购买页实时价为准**。买完在控制台拿到**公网 IP**。

> 备选：若你已有 ECS，也能用——差异只在「防火墙」那步要配**安全组入方向**放行 80/443（见第八步）。

## 第二步：连接服务器

在**本机 PowerShell** 里（Windows 10/11 自带 OpenSSH，无需装任何东西）：

```powershell
ssh root@你的公网IP
```

- 首次登录问 `Are you sure you want to continue connecting?` → 输 `yes` 回车
- 然后输入购买时设的 **root 密码**（输入时不显示字符，正常，敲完回车）

> 连不上排查：① 阿里云控制台「防火墙」要放行 **22** 端口（轻量默认已放行）；
> ② 密码错误可在控制台「重置密码」后重启实例再试。

## 第三步：装环境（用 setup-server.sh 一键装）

### 3.1 本机：把脚本传到服务器

新开一个 PowerShell 窗口（保持 ssh 那个窗口不断），在项目目录执行：

```powershell
cd d:\hs-copilot-web
scp .\deploy\setup-server.sh root@你的公网IP:/root/
```

### 3.2 服务器：执行脚本

回到 ssh 窗口（已在服务器上）：

```bash
bash /root/setup-server.sh
```

脚本会依次：更新系统 → 装 Node 24 → 验证 `node:sqlite` → 装 pm2 → 装 nginx →
建 `/opt/hs-copilot` 和 `/var/log/hs-copilot`。**幂等，可重复跑。**

看到最后一行 `==> 环境就绪` 即成功。中途 `node:sqlite` 会打印一行
`ExperimentalWarning`，属正常，不是错误。

> 想手动逐条装也可以，脚本里的命令都是标准 apt/npm 操作，逐行复制即可。

## 第四步：本机打包 + 上传代码

### 4.1 本机：打包（用 pack.ps1）

在**本机 PowerShell** 执行：

```powershell
cd d:\hs-copilot-web
powershell -ExecutionPolicy Bypass -File .\deploy\pack.ps1
```

产物默认在 `D:\hs-copilot.tar.gz`（约 7MB）。脚本会自动校验并打印
`校验通过：关键文件齐全，敏感/巨大内容已排除`。

> 已排除：`.git`(562MB)、`tools/backup`(130MB)、`tools/raw`(67MB)、
> `*.db-shm/wal`、`server.log`、`__pycache__`、**`llm.config.json`（密钥，下一步单独传）**。

### 4.2 本机：上传代码包

```powershell
scp D:\hs-copilot.tar.gz root@你的公网IP:/root/
```

### 4.3 服务器：解压到 /opt/hs-copilot

```bash
cd /opt/hs-copilot
tar -xzf /root/hs-copilot.tar.gz
ls    # 应看到 server.js、index.html、hs_copilot.db、deploy/、package.json 等
```

## 第五步：放密钥 llm.config.json

密钥文件被打包脚本故意排除了，现在**单独上传**：

```powershell
# 本机 PowerShell
cd d:\hs-copilot-web
scp .\llm.config.json root@你的公网IP:/opt/hs-copilot/
```

**在服务器上锁死权限**（只允许 root 读）：

```bash
chmod 600 /opt/hs-copilot/llm.config.json
```

> 为什么可以放心放：静态目录已加固，HTTP 请求 `/llm.config.json` 返回 **403**（已实测）。
> 想彻底不落盘也可改用环境变量 `LLM_API_KEY` + `LLM_BASE_URL`（写进 ecosystem 的 env），
> 但那样只支持单通道，会丢失 `llm.config.json` 里 `providers` 数组的备用免费模型。

---

## 第六步：启动服务（pm2）

在**服务器**上：

```bash
cd /opt/hs-copilot
pm2 start deploy/ecosystem.config.cjs
pm2 save
pm2 startup      # 复制它输出的那一行命令再执行一次，实现开机自启
```

`ecosystem.config.cjs` 已配好关键项：`HOST=127.0.0.1`、`PORT=7100`、`HS_RULINGS=0`、
内存超 400M 自动重启、日志写 `/var/log/hs-copilot/`。

验证服务活着：

```bash
curl http://127.0.0.1:7100/api/health
```

应看到类似：`{"ok":true,"db":true,"llm":true,"rulings":{"enabled":false,...}}`

- `db:false` → 没找到 `hs_copilot.db`，确认它在 `/opt/hs-copilot/` 根目录
- `llm:false` → 密钥没读到，检查 `llm.config.json` 是否上传、内容是否含 `apiKey`

---

## 第七步：配 Nginx 对外

把项目自带的 `deploy/nginx-hs-copilot.conf` 内容写到服务器 nginx 配置里，
**关键是把 `server_name` 改成你的公网 IP**（纯 IP 访问也可写 `_` 作通配）。

```bash
# 服务器上
nano /etc/nginx/sites-available/hs-copilot
# 粘贴 deploy/nginx-hs-copilot.conf 的内容，把 server_name 那行改成：
#     server_name 你的公网IP;      （或 server_name _;）
# 保存退出：Ctrl+O 回车，Ctrl+X

ln -sf /etc/nginx/sites-available/hs-copilot /etc/nginx/sites-enabled/hs-copilot
rm -f /etc/nginx/sites-enabled/default
nginx -t                     # 必须显示 syntax is ok / test is successful
systemctl reload nginx
```

> 配置里 `proxy_read_timeout 180s` 是**关键**：大模型一次调用可能几十秒，
> nginx 默认 60s 就掐断，表现为「点了没反应」。项目自带的配置已经设好，别删。

## 第八步：开防火墙

### 8.1 阿里云控制台防火墙（**必做**，这是阿里云的主要闸门）

- **轻量应用服务器**：控制台 → 你的实例 → 「防火墙」标签 → 添加规则，放行：
  - `TCP 80`（HTTP）
  - `TCP 443`（HTTPS，为以后备案上证书备用）
  - `TCP 22`（SSH，一般默认已放行，确认在列）
- **ECS**：控制台 → 实例 → 「安全组」→ 配置规则 → 入方向，放行同样的 80/443/22。

> **不要**放行 7100。外网只走 nginx 的 80/443，7100 只在内网被 nginx 反代。

### 8.2 系统 ufw（可选，双保险）

```bash
ufw allow 22
ufw allow 80
ufw allow 443
ufw enable          # 提示会中断连接，输 y；因为已放行 22，SSH 不会断
ufw status
```

> 顺序很重要：**先 allow 22 再 enable**，否则可能把自己 SSH 锁在门外。

## 关于域名和备案（阿里云）

- **阶段一（当前，推荐）**：直接用 `http://公网IP/` 访问，**不需要备案**，今天就能用。
- **阶段二**：买域名 → 阿里云 DNS 解析到公网 IP → **必须 ICP 备案**。
  国内服务器 + 域名，未备案会被拦在 80 端口访问不了。
  阿里云备案入口：`https://beian.aliyun.com`（阿里云有独立备案系统，约 10~20 天）。
- 备案通过后才能申请 HTTPS 证书：

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名
certbot renew --dry-run      # 验证自动续期
```

## 维护提醒：加前端文件要登记白名单

`server.js` 里有静态资源白名单（约 936 行）：

```js
const STATIC_ALLOW = new Set([
  '/index.html', '/styles.css',
  '/app.js', '/confirm-logic.js', '/decision-logic.js', '/ruling-view.js',
  '/favicon.ico'
]);
```

以后新增前端 css / js / 图片，必须把路径加进这个集合，否则线上返回 **403**
（本地也一样，所以本地就能发现问题）。这是为挡住密钥和源码泄露故意设的门槛。
